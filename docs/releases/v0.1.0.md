# v0.1.0

## Highlights

- First Linux-focused release candidate for `pwned-check`, a password breach checker that reads candidates from stdin and checks k-anonymity range responses without logging plaintext passwords.
- Ships the `pwned-check-pam-helper` integration for `pam_exec.so expose_authtok` deployments.
- Adds the optional native Linux PAM module, `pam_pwned_check.so`, with safe conversation strings, checker fork/exec isolation, hard timeout handling, safe syslog events, and no-secret-output tests.
- Includes Linux package artifacts for `amd64` and `arm64`, plus native PAM packaging paths for Debian/Ubuntu, Fedora/RHEL, Arch Linux, and Alpine Linux-PAM deployments.
- Documents checker contract, logging policy, operations, troubleshooting, distro testing, rollout, rollback, and release provenance.

## Operator impact

- Existing deployments should treat this as the first public release line and deploy in dry-run mode before enforcement.
- The checker contract is stable for this pre-`v1.0.0` release: exit `0` means allowed or fail-open provider outage, exit `1` means pwned, exit `2` means configuration/input failure, and exit `3` means fail-closed provider failure.
- The native PAM package installs files only; operators must explicitly enable the PAM integration through the distro-specific path.
- The native PAM module can collect the password through Linux PAM's `pam_get_authtok` helper when no earlier password module has populated `PAM_AUTHTOK`, so Debian/Ubuntu deployments do not need to install or retain `pam_pwquality` solely for token collection.
- Debian and Ubuntu native packages use `pam-auth-update`; Fedora/RHEL packages use authselect helpers; Arch and Alpine Linux-PAM packages use manual helper scripts with timestamped rollback.
- macOS and Windows release artifacts are intentionally not published yet.

## Known limitations

- Native PAM is Linux-only.
- Release signing and native package repository publication are documented but require the release signing environment and private keys outside this repository.
- Count-based `min_count` policy is supported by the checker and native module, but operators should keep package rollouts in dry-run mode until local password-change flows and rollback are rehearsed.
