# v0.1.1

## Highlights

- Patch release for the native Linux PAM delivery track after the first public `v0.1.0` release.
- Makes `pam_pwned_check.so` self-sufficient for token collection by using Linux PAM's `pam_get_authtok` helper when `PAM_AUTHTOK` is not already populated.
- Stabilizes native checker exec-failure handling by detecting path-qualified missing or non-executable checkers before fork/exec.
- Fixes Alpine native PAM package placement across the persistent Alpine VM and pinned Alpine Docker image.
- Keeps local release validation VM-first for Debian, Ubuntu, Fedora, and Alpine, with Docker retained for no-VM targets and CI parity.

## Operator impact

- Debian/Ubuntu operators no longer need to install or retain `pam_pwquality` solely to populate `PAM_AUTHTOK` for `pam_pwned_check.so`.
- Existing PAM stacks can enable the native module directly before `pam_unix.so use_authtok`; accepted passwords continue through the stack using the same PAM token.
- Misconfigured checker paths fail deterministically and are easier to diagnose through the native module failure events.
- Alpine operators should use the updated package path because it installs the native PAM module in the loader locations observed across current test targets.
- The native PAM package still installs files only; operators must explicitly enable enforcement and should validate rollback on a disposable host or VM first.

- Exact `0.1.0-rc1` native package smoke results informed this patch release.

## Known limitations

- Native PAM remains Linux-only.
- Published GitHub release assets are the Linux checker/helper tarballs; native PAM package repository publication and package signing remain documented release-environment tasks.
- Operators should keep new PAM deployments in dry-run mode until local password-change flows and rollback are rehearsed.
