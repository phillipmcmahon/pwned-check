# v0.1.2

## Highlights

- Publishes native Linux PAM package assets through the GitHub release workflow.
- Adds release-time native package assembly for Debian/Ubuntu `.deb`, Fedora/RPM `.rpm`, Arch Linux, and Alpine Linux-PAM packages.
- Includes per-package checksums, build metadata, aggregate native package checksums, and native package provenance alongside the existing Linux checker/helper tarballs.
- Keeps native package publication atomic with release creation, which is required because published GitHub releases are immutable.

## Operator impact

- Ubuntu operators can install the native module directly from the release `.deb` instead of cloning the repository and building locally.
- Fedora/RHEL-family, Arch, and Alpine Linux-PAM operators now have downloadable package artifacts from the release page.
- Package installation still places files only. Operators must explicitly enable the PAM integration through the distro-specific enablement path and should validate rollback before enforcement.
- Native package artifacts are unsigned in this release because package-signing keys are not yet configured in the release environment.

## Validation

- The native package release workflow builds the Debian/Ubuntu package on Ubuntu and builds/smokes Fedora/RPM, Arch, and Alpine package paths through distro containers before release creation.
- The aggregate `native-pam-SHA256SUMS.txt` and `native-pam-provenance.json` are generated from the exact native package files attached to the release.
- Prior `v0.1.1` VM validation remains the behavioral acceptance baseline: Ubuntu active enforcement without `pam_pwquality`, Debian `.deb` smoke, Fedora RPM/SELinux assessment, and Alpine Linux-PAM package behavior were all validated.

## Known limitations

- Native PAM remains Linux-only.
- Native packages are attached to GitHub Releases but are not yet distributed through apt, dnf/yum, Arch, or Alpine package repositories.
- Package-based install examples are documented in [Operations](../operations.md#install-from-github-releases).
- Package signatures and repository metadata signing remain the next release-infrastructure step.
