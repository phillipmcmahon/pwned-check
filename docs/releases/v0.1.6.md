# v0.1.6

## Highlights

- Tightens the release process so pushed `main` CI is watched to completion before an annotated release tag is created.
- Adds `gh auth status` preflights to GitHub Actions monitoring helpers so release maintainers get a clear authentication failure before workflow lookup starts.
- Consolidates operator documentation around install, enablement, rollback, testing, and release procedures, removing stale development-era document overlap.
- Keeps the current native package documentation payload operator-focused by excluding maintainer-only production release gate notes from bootstrap package bundles.
- Records expected local arm64 Docker pre-push duration so maintainers can distinguish normal validation time from a stalled test run.

## Operator impact

- No checker, provider, CLI, or native PAM runtime behavior changes are intended in this release.
- Ubuntu, Debian, Fedora, Rocky, Alpine, and Arch operational guidance remains aligned with the current package and VM smoke-test coverage.
- GitHub Release native packages remain the bootstrap distribution channel; signed apt, RPM, Alpine, and Arch package repositories are still tracked as Epic 8 production-readiness work.

## Validation

- Local shell validation passed for the release helper and package scripts changed in this release.
- Stale documentation references to removed development-era docs were checked across the tree before release prep.
- Local pre-push validation will run before `main` is pushed for this release, including Go tests, Rust native PAM tests, VM package smokes, arm64 Docker smokes, and Linux package builds.
- GitHub CI on `main` will be monitored to completion before `v0.1.6` is tagged.
- The tag-triggered CI and release workflow will rebuild release artifacts from this tag before publishing.

## Known limitations

- Native PAM remains Linux-only.
- Native packages are attached to GitHub Releases but are not yet distributed through signed apt, dnf/yum, Arch, or Alpine package repositories.
- Repository signing keys, repository metadata publication, public key bootstrap docs, and repository-install smoke tests remain Epic 8 production release-infrastructure work.
