# v0.1.7

## Highlights

- Records the signed apt, RPM, Arch, and Alpine repository publication path as
  the preferred production-style install route for native PAM packages, while
  keeping GitHub Release assets as the immutable bootstrap and recovery source.
- Adds scheduled live repository endpoint monitoring for public keys, signed
  metadata, package visibility, and Alpine package payload availability without
  installing packages or changing PAM state.
- Adds live repository smoke orchestration across the persistent Ubuntu,
  Debian, Fedora, Rocky, and Arch VMs, with Alpine arm64 endpoint validation
  recorded until matching real-host coverage exists.
- Documents VM fleet recovery policy and per-distro VM rebuild runbooks so the
  release-validation hosts can be recreated without relying on memory.
- Tightens release operations with externalized NAS archive configuration,
  shared release-helper preflights, annual key-rotation rehearsal guidance, and
  explicit monitor fingerprint update steps during key rotation.

## Operator impact

- Repository-backed native PAM installation is now the normal documented path
  for operators. Manual GitHub Release package downloads remain available for
  bootstrap, recovery, and immutable artifact inspection.
- No checker, provider, CLI, or PAM enforcement behavior change is intended in
  this release. The user-facing password rejection and temporary checker-failure
  messages are unchanged.
- The endpoint monitor is non-mutating: it validates published repository
  metadata and payload visibility, but it does not install packages or alter PAM
  configuration on any host.
- Release validation remains VM-first for supported amd64/x86_64 distro
  families, with Docker/QEMU used for CI parity and documented ARM gaps.

## Validation

- `scripts/native-pam-repo-endpoint-check.sh` passed locally against the live
  published endpoints after adding Alpine package payload URL verification.
- Local release validation passed from the release-prep tree before `main` was
  pushed, including Go tests, Rust native PAM tests, VM package smokes, arm64
  Docker smokes, and Linux package builds.
- GitHub CI on `main` was monitored to completion before `v0.1.7` was tagged.
- The tag-triggered CI and release workflow rebuilt release artifacts from this
  tag before publishing.

## Known limitations

- Native PAM remains Linux-only.
- Apt `arm64` and RPM `aarch64` metadata still await native arm64/aarch64 VM
  smoke coverage. Docker/QEMU coverage reduces risk but does not replace the
  persistent VM release gate.
- Arch Linux packaging remains `x86_64` only.
- Alpine repository publication currently validates the published `aarch64`
  endpoint, while the persistent Alpine VM remains `x86_64`.
