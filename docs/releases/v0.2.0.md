# v0.2.0

## Highlights

- Removes the legacy `pwned-check-pam-helper` and `pam_exec.so expose_authtok`
  PAM integration path.
- Makes the native Linux PAM package the only supported PAM integration.
- Adds persistent arm64/aarch64 VM smoke coverage for Debian, Ubuntu, Fedora,
  Rocky, and Alpine.
- Reorganizes operator documentation around signed repository installation,
  package enablement, rollback, and removal.
- Fixes repository validation details for Alpine public-key filenames and Arch
  package description extraction.

## Operator impact

- Operators should install and enable the native PAM package with the
  documented `pwned-check-pam-enable-dry-run`,
  `pwned-check-pam-enable-enforce`, and `pwned-check-pam-disable` commands.
- Pre-v0.2 test hosts with a hand-written PAM line invoking
  `pwned-check-pam-helper` must remove that `pam_exec.so expose_authtok` line
  before enabling the native package.
- Native PAM package installation remains Linux-only.
- No checker policy, HIBP provider, fail-open/fail-closed, or user-facing
  password rejection message change is intended in this release.

## Validation

- Local release validation passed from the release-prep tree with
  `make validate`, including Go checks, Rust native PAM checks, package builds,
  and the persistent VM smoke matrix.
- GitHub CI on `main` was monitored to completion before `v0.2.0` was tagged.
- The tag-triggered release workflow rebuilt release artifacts from this tag
  before publishing.

## Known limitations

- Native PAM remains Linux-only.
- Arch Linux packaging remains `x86_64` only because there is no supported
  Arch Linux ARM target for this project.
- Repository publication and production readiness remain governed by the
  production release gate; do not describe repository-backed deployment as
  production-ready unless that gate is satisfied for the release.
