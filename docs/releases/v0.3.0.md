# v0.3.0

## Highlights

- Adds the Linux production-baseline closeout track for declaring the package
  and repository path production-ready.
- Adds a single Linux package install guide for the signed repository path.
- Keeps the native PAM package as the only supported Linux PAM integration.
- Advances the native PAM Rust crate metadata to `0.3.0` with the paired
  release-version helper.

## Operator impact

- New Linux operators should start with
  [Linux package install](../linux-install.md) for repository setup, package
  installation, dry-run, enforcement, rollback, removal, and emergency recovery.
- The signed repositories remain the preferred installation channel for
  Debian/Ubuntu, Fedora/RHEL/Rocky, Arch Linux, and Alpine Linux-PAM where the
  documented architecture is published.
- Package installation still only places files on disk. PAM enablement remains
  explicit and should start with `pwned-check-pam-enable-dry-run`.
- The helper-based `pam_exec.so expose_authtok` integration remains removed;
  use the native PAM package path only.

## Validation

- Version metadata was prepared with
  `make prepare-release-version VERSION=v0.3.0`.
- Local validation and GitHub Actions validation were completed before the
  signed release tag was pushed. The signed tag message records the final
  validated commit SHA and GitHub Actions run URL used for publication.

## Known limitations

- Arch Linux ARM is not targeted because Arch Linux ARM is a separate
  downstream ecosystem rather than an official Arch Linux architecture target.
- Alpine package repository publication remains Linux-PAM-only; BusyBox-only
  authentication is outside scope.
- macOS and Windows production integrations remain intentionally deferred until
  platform signing and security requirements are designed and validated.
